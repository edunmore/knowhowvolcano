# 7-Minute Microlearning Loop

## When to use
Use this loop to design one microlearning unit. It is a tool for turning internal know-how into short, effective learning experiences that aim for real-world performance, not just recall. It is presented as a small toolbox to reuse across topics to combat [[Interference (Learning)]] where learners freeze or forget under pressure.

## Steps
1.  **Choose one Outcome Ladder rung as the target (A, B, C, or D).** This defines the performance goal, separating outcomes like recall from [[Transfer (Learning)]].
2.  **Write one “observable pass condition” (what you can see or measure).**
3.  **Create one short scenario with a constraint** (e.g., time pressure, an annoyed colleague, missing data).
4.  **Offer two actions:** the intended action and a tempting wrong action.
5.  **Ask for a choice *and* a one-sentence reason.**
6.  **Give feedback in two layers:** first a short [[Rule of Thumb]], then a deeper explanation. This is the [[Two-Speed Feedback]] principle.
7.  **Add a “next repetition” prompt:** when and how to repeat (tomorrow, next meeting, or next real case).

## Failure modes
- **Targeting the wrong rung:** Testing only recall (Rung A) while performance stays flat.
- **Exceeding the [[Friction Budget]]:** Adding too much content, theory, or complexity, causing learners to quit or guess.
- **Mixing multiple skills** in one unit, which raises friction without improving transfer.
- **Assuming recognition equals performance:** Believing that if a learner understands once, they will perform later under stress. [[Transfer (Learning)]] requires spaced repetition and practice under constraints.
