# 7-Minute Microlearning Loop

## When to use
Use this procedure to design a single [[Microlearning]] unit that aims to build skill transfer, especially when the goal is to help learners perform under real-world constraints like time pressure or stress. It is intended to combat [[Interference (Learning)]] where learners freeze or forget steps in practice.

## Steps
The procedure consists of seven steps:
1.  **Choose one [[Outcome Ladder]] rung** as the target (A, B, C, or D).
2.  **Write one observable pass condition** (what you can see or measure).
3.  **Create one short scenario with a constraint** (e.g., time pressure, an annoyed colleague, missing data).
4.  **Offer two actions**: the intended action and a tempting wrong action.
5.  **Ask for a choice *and* a one-sentence reason**.
6.  **Give [[Two-Speed Feedback]]**: first a short [[Rule of Thumb]], then a deeper explanation.
7.  **Add a “next repetition” prompt**: specify when and how to repeat the practice (e.g., tomorrow, next meeting).

## Failure modes
- **Targeting the wrong rung**: Creating a unit that only tests recall (Rung A) while celebrating progress, while actual performance stays flat.
- **Exceeding the [[Friction Budget]]**: Adding too much content, new terms, or steps, causing learners to quit or guess instead of engaging in [[Deliberate Practice]].
- **Believing "more content means more learning"**: Adding extra examples or theory can raise friction without improving [[Transfer (Learning)]].
- **Assuming recognition equals performance**: Believing that if a learner understands a concept once, they will perform it later, ignoring the need for spaced repetition and practice under constraints.
