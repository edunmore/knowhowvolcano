# 7-Minute Microlearning Loop

## When to use
Use this procedure to design a single microlearning unit, particularly when the goal is to turn internal know-how into training that helps learners perform under real-world constraints and avoid [[Interference]].

## Steps
1.  Choose one [[Outcome Ladder]] rung (A, B, C, or D) as the target for the unit.
2.  Write one "observable pass condition" (what you can see or measure).
3.  Create one short scenario that includes a constraint (e.g., time pressure, an annoyed colleague, missing data).
4.  Offer two possible actions: the intended action and a tempting wrong action.
5.  Ask the learner to make a choice *and* provide a one-sentence reason for it.
6.  Provide [[Two-Speed Feedback]]: a fast layer with a [[Rule of Thumb]], then a slow layer with a deeper explanation.
7.  Add a "next repetition" prompt specifying when and how to repeat the practice (e.g., tomorrow, in the next meeting, or on the next real case).

## Failure modes
Not specified in this source. Open questions: (1) What happens if a designer targets [[Transfer (Learning)]] without first establishing [[Performance]]? (2) How does exceeding the [[Friction Budget]] manifest within this specific loop structure?
